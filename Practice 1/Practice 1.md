# 当下AIGC在游戏音频设计中的应用调研

## 1. 研究背景

传统游戏音频设计的过程以及现存痛点:

1. **语音**: 撰写台词脚本 -> 邀请配音演员录音 -> 进行后期修音,降噪,单句导出wav -> 音频设计师在中间件中配置语音事件,抢占逻辑 -> 打包成SoundBank进入游戏引擎.

> **痛点**: 后期改台词需要演员返回录音棚重录,大量NPC台词成本高,需要大量资金.

2. **音乐**: 确定音乐风格 -> 作曲家作曲,制作管弦乐 -> 输出分轨Stem -> 音频设计师利用中间件做自适应交互音乐 -> 打包成SoundBank导入游戏引擎.

> **痛点**: 作曲家负责作曲,而由音频设计师设计交互逻辑,调试非常麻烦.

3. **音效**: 梳理所需要的音效清单 -> 商用音效库素材叠加修改/拟音棚实物录制Foley标准化导出wav -> 音频设计师在中间件设置随机播放组,3D空间衰减,环境混响 -> 打包成SoundBank集成进游戏引擎进行反复调试试听.

> **痛点**: 很多音效缺少现实原型,试错耗时长.

生成式音频AI出现之后,音频设计师可以通过提示词快速输出语音、背景音乐以及音效;同时Text-to-Video多模态模型还可以完成“从画面反推生成音频”的新路径,并且可以从“预先制作音频资源”,探索运行时动态化生成音频的可能.

## 2. AIGC在游戏音频三大应用方向: Voice/Music/SFX

### 2.1. Voice-AI角色配音

#### 2.1.1. 主要技术

1. **通用TTS文本转语音**: 输入台词 + 情绪参数,用AI直接生成角色语音;

2. **语音克隆**: 参考人声,复刻角色声线;

3. **动态实时对话语音**: 大语言模型实时生成对话文本,流式TTS输出语音,能用于动态NPC交互.

#### 2.1.2. 开发场景

1. **原型阶段临时配音**: 在游戏的前期版本可以快速生成临时语音,帮助策划、导演验证叙事节奏,不需要立刻邀请真人录音.

2. **游戏多语言本地化**: 针对大量路人NPC的海量台词可以使用AI语音,减少配音演员的工作量.

3. **游戏运行时动态NPC台词**: NPC能够根据玩家行为实时生成对话文本,并且能够即时合成语音输出,实现自由的交互叙事.

4. **口型自动对齐**: AI进行语音输出之后,还能配套AI口型生成工具,生成配套的口型动画.

#### 2.1.3. 主流工具

| 工具 | 特点 | 游戏场景用途 |
| :----: | :----: | :----: |
| EventLabs | 具有高表现力的人声,支持API流式输出,支持语音克隆 | 角色配音、本地化、原型配音 |
| VITS/Coqui-TTS | 本地部署、端侧推理 | Unity/Unreal引擎内置,在离线运行时语音合成 |
| Azure Neural TTS | 大规模多语种官方TTS | 商业游戏本地化流水线 |

#### 2.1.4. 当前局限性

1. AI生成的语音在高情绪的片段不如真人配音演员,情绪层次单薄.

2. 语音克隆有严重的伦理版权风险,容易侵权.

3. 端侧实时流式合成延时问题,主机、移动端设备算力难以本地跑高质量大模型.
