# 当下AIGC在游戏音频设计中的应用调研

## 1. 研究背景

传统游戏音频设计的过程以及现存痛点:

- **语音**: 撰写台词脚本 -> 邀请配音演员录音 -> 进行后期修音,降噪,单句导出wav -> 音频设计师在中间件中配置语音事件,抢占逻辑 -> 打包成SoundBank进入游戏引擎.

> **痛点**: 后期改台词需要演员返回录音棚重录,大量NPC台词成本高,需要大量资金.

-  **音乐**: 确定音乐风格 -> 作曲家作曲,制作管弦乐 -> 输出分轨Stem -> 音频设计师利用中间件做自适应交互音乐 -> 打包成SoundBank导入游戏引擎.

> **痛点**: 作曲家负责作曲,而由音频设计师设计交互逻辑,调试非常麻烦.

-  **音效**: 梳理所需要的音效清单 -> 商用音效库素材叠加修改/拟音棚实物录制Foley标准化导出wav -> 音频设计师在中间件设置随机播放组,3D空间衰减,环境混响 -> 打包成SoundBank集成进游戏引擎进行反复调试试听.

> **痛点**: 很多音效缺少现实原型,试错耗时长.

生成式音频AI出现之后,音频设计师可以通过提示词快速输出语音、背景音乐以及音效;同时Text-to-Video多模态模型还可以完成“从画面反推生成音频”的新路径,并且可以从“预先制作音频资源”,探索运行时动态化生成音频的可能.

## 2. AIGC在游戏音频三大应用方向: Voice/Music/SFX

### 2.1. Voice-AI角色配音

#### 2.1.1. 主要技术

- **通用TTS文本转语音**: 输入台词 + 情绪参数,用AI直接生成角色语音;

- **语音克隆**: 参考人声,复刻角色声线;

- **动态实时对话语音**: 大语言模型实时生成对话文本,流式TTS输出语音,能用于动态NPC交互.

#### 2.1.2. 开发场景

- **原型阶段临时配音**: 在游戏的前期版本可以快速生成临时语音,帮助策划、导演验证叙事节奏,不需要立刻邀请真人录音.

- **游戏多语言本地化**: 针对大量路人NPC的海量台词可以使用AI语音,减少配音演员的工作量.

- **游戏运行时动态NPC台词**: NPC能够根据玩家行为实时生成对话文本,并且能够即时合成语音输出,实现自由的交互叙事.

- **口型自动对齐**: AI进行语音输出之后,还能配套AI口型生成工具,生成配套的口型动画.

#### 2.1.3. 主流工具

| 工具 | 特点 | 游戏场景用途 |
| :----: | :----: | :----: |
| EventLabs | 具有高表现力的人声,支持API流式输出,支持语音克隆 | 角色配音、本地化、原型配音 |
| VITS/Coqui-TTS | 本地部署、端侧推理 | Unity/Unreal引擎内置,在离线运行时语音合成 |
| Azure Neural TTS | 大规模多语种官方TTS | 商业游戏本地化流水线 |

#### 2.1.4. 当前局限性

- AI生成的语音在高情绪的片段不如真人配音演员,情绪层次单薄.

- 语音克隆有严重的伦理版权风险,容易侵权.

- 端侧实时流式合成延时问题,主机、移动端设备算力难以本地跑高质量大模型.

### 2.2. Music-AI游戏音乐

游戏音乐分为静态配乐与自适应交互音乐,后者是游戏音频独有的难点: 音乐需要跟随玩家的状态(战斗、探索、受伤)实时平滑变化.

#### 2.2.1. 两种AI音乐工作模式

1. **完整片段生成模式(Suno、Udio、AIVA)**: 输入提示词能够输出完整音频曲目,适合作为菜单音乐、CG过场背景音乐以及原型阶段参考配乐.

2. **分轨Stem生成模式(Soundraw、Mubert、Beatoven)**: AI输出分轨音轨(鼓组、弦乐、贝斯),音频设计师拿到分轨之后导入音频中间件,手动搭建交互逻辑,实现音乐的变换.

#### 2.2.2. 使用场景

- 独立游戏、小游戏的背景音乐制作.

- 原型不断迭代,能够快速尝试不同情绪、不同风格的配乐方案.

- 开放世界循环背景音乐

- UGC游戏: 玩家自建地图,能够根据地图自动生成描述提示词,生成对应地图背景音乐.

#### 2.2.3. 现存技术短板

- AI生成的音频自动生成无缝循环的能力比较弱,大部分生成的片段无法直接循环,需要人工修改.

- 长时间的音乐会存在跑调等错误.

- 存在版权风险.

### 2.3. SFX-AI游戏音效

游戏音效包括UI音效、打击音效、魔法音效、脚步声等等.

> 传统方案: 商用音效素材库 + 拟音录音.对于科幻题材不存在现实世界的音效时,AI生成有着明显优势.

#### 2.3.1. 技术路线(Text-to-SFX)

输入文本提示词描述音效,能够直接输出音效片段.

> 代表模型: Meta AudioGen、ElevenLabs-SFX、Stable-Audio

> 示例: Fast sword slash, metal whoosh, short 0.3s, dry sound, fantasy melee(快速挥剑破空声,金属气流呼啸,时长0.3s,干声,奇幻近战武器)

#### 2.3.2. 工作流

1. **初期创意阶段**: 音频设计师用AI快速生成多个版本的音效,作为参考.

2. **后期加工**: AI输出的音效往往信噪比等参数达不到游戏工程标准,设计师还需要做滤波、压缩等工作后才能导入引擎.

#### 2.3.3. 痛点

- 脚步声、枪械等现实类物理音效等,专业商用素材库效果仍好于AI生成.

- AI生成音效随机性很强,尽管是同一个提示词,最后的生成结果差异依旧很大,很难稳定复现同一个目标音效.

- 缺少精细的参数控制.

## 3. Text-to-Audio与Text-to-Video

### 3.1. Text-to-Audio

> 流程: 文本提示词 -> AI模型 -> WAV音频文件

- 优势: 管线简单,设计师直接撰写提示词,适合离线批量制作音频资产.也可以通过API接口在游戏运行时调用云端服务动态生成音频,适配UGC游戏.

- 劣势: 完全依靠自然语言描述声音,而对于复杂的声音场景,文字很难完整描述声音细节.

### 3.2. Text-to-Video

1. 先生成视频, 再由画面语义反向生成适配音频
- 流程: 场景描述生成游戏画面帧 -> 画面语义识别提取环境、物体动作信息 -> 自动生成提示词送入音频AI模型生成音频.

2. 已有无声游戏动画CG录频,AI自动完成音画同步配音效,提升了游戏动画、过场CG的后期制作效率.

**对于游戏开发的意义**

在程序化生成游戏中,引擎生成地形、场景、物体之后,不需要人工再逐个配置音频资源,引擎能够读取场景然后自动生成对应音频,为无限生成的开放世界、玩家自建UGC地图提供了音频解决方案.

**短板**: 多模态链路更长,推理耗时更高,音画自动对齐精度不稳定.现阶段只是处于学术原型阶段,尚未大规模进入正式商业游戏项目.

## 4. 现存风险与挑战

### 4.1. 技术层面

- **实时运行生成的延迟问题**: 高质量音频生成耗时较长且云端API具有网络延迟,本地端侧受算力约束,运行时动态生成音频还很难大规模用于正式发售游戏,现在大多用于离线生成资源.

- **生成结果不稳定**: 相同的提示词所生成的结果音色、风格偏移,同一个角色的AI语音前后情绪不稳定,AI配乐前后调性不一致.

- **游戏交互音频短板**: AI不擅长处理音乐平滑过渡,以及分层变化,交互逻辑仍依赖中间件人工设计.

### 4.2. 版权与法律风险

- AI训练数据版权存在争议.

- 语音克隆存在侵权风险.

- 完全由AI独立生成的音频资产著作权归属模糊.

### 4.3. 行业伦理

AIGC不会直接取代音频设计师、配音演员,但是会改变岗位的工作内容.设计师更多转向提示词设计、素材筛选、后期精加工、交互音频逻辑设计.原型阶段使用临时AI配音,会减少很多前期试录的工作量等等.

## 5. 未来展望

- 能够普及一些更加轻量化的音频AI模型.

- 模型能够更好支持分轨输出.

- 不仅仅依靠文本或者画面,若能将游戏引擎中的场景数据输入进音频生成模型,生成出来的模型将会更加符合游戏.

- 行业相关法规、版权应该逐步完善.

## 6. 总结

AIGC在游戏音频设计领域已经占据一席之地,加快了游戏音频原型的迭代速度,降低了独立游戏开发者音频素材的生成门槛,但技术仍然存在明显短板,如AI不擅长交互、生成结果不稳定,存在版权问题等等.未来随着轻量化音频模型的普及,运行时动态音频生成可能会成为未来游戏音频设计的重要发展方向.
